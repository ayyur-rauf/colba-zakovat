## 2. Nima qilindi

### 2.1. Yadro
- **Xodimlar ro'yxati** Excel'dan yuklanadi (o'zbekcha/ruscha sarlavhalar). Xato bo'lsa hech narsa saqlanmaydi, xato qatorlar ko'rsatiladi.
- **Kirish:** Telegram, Google, email kod. Faqat ro'yxatdagi xodim kiradi; begona — admin tasdig'ini kutadi. Bir akkauntga bir nechta usul bog'lanadi. Ishdan ketgan yoki bloklangan xodimning eski tokeni ham darhol ishlamay qoladi.
- **Rollar** modul va mavsum bo'yicha: bosh admin, Tashkiliy guruh, boshlovchi, sekundant, hisob hay'ati, tashkilotchi, tekshiruvchi.
- **Mavsum = o'quv yili.** Bir vaqtda bitta faol mavsum.
- **Ball reestri:** ball o'chirilmaydi va o'zgarmaydi — faqat sababli tuzatuvchi yozuv. Kim, qachon, nima uchun — hammasi ko'rinadi.
- **Harakatlar jurnali:** muhim amallar (tasdiqlash, natija, rol berish) yoziladi, uni hech kim o'zgartira olmaydi.

### 2.2. Zakovat ("Colba ligasi")
Nizomning qoidalari tizimga kiritilgan — ularni chetlab o'tib bo'lmaydi:

| Qoida | Nizom |
|---|---|
| Har oyning 3-shanbasiga o'yinlar jadvali avtomatik | 1.2 |
| O'yinga 1 kundan kam qolganda o'zgarish — faqat sabab bilan | 1.4 |
| Jamoada 4–8 o'yinchi, bir o'yinchi — bitta jamoa, nom takrorlanmaydi | 3.2, 3.3 |
| Mavsum davomida nom va tarkib qulflanadi | 3.4, 3.5 |
| Ro'yxatdan o'tish o'yindan 1 kun oldin yopiladi; joy to'lsa — navbat | 3.2, 4.1 |
| Raundda ≤6 o'yinchi, almashtirish faqat raundlar orasida | 5.2 |
| 3 o'yinchidan kam bo'lgan savollar hisobga olinmaydi | 3.6, 4.3 |
| Ball, savol reytingi R = N + 1, J; teng bo'lsa — qo'shimcha o'yin | 6.1, 8.1–8.3 |
| Apellyatsiya: faqat sardor, dalil bilan, yakuniy natijagacha | 7.2–7.4 |
| Chiqqan/chetlatilgan jamoa ballari nolga, boshqalarniki o'zgarmaydi | 3.7–3.9 |

Hisob hay'ati uchun javoblar jadvali (jamoalar × 36 savol), katta ekran rejimi (reytingni yashirish mumkin), mashq o'yinlari (ball bermaydi).

### 2.3. Kitobxonlik
Ovoz berish → eng ko'p ovoz olgan kitob (teng bo'lsa tashkilotchi tanlaydi) → hammaga bir xil 10 kun o'qish → izoh (matn yoki fayl) → tekshiruvchi mezonlar bo'yicha baholaydi → tashkilotchi tasdiqlaydi → ball shaxsiy hisobga.
- PDF kitoblar ochiq havolada emas — faqat kirgan xodimga.
- Muddatni alohida xodimga sabab bilan uzaytirish mumkin.
- Bir nechta tekshiruvchi → o'rtacha ball; reestrga butun songa yaxlitlanadi (19,5 → 20).
- Shaxsiy kartochka; reyting jadvali sozlama bilan ochiladi.

## 3. Professional darajaga chiqish uchun oldinda turgan ishlar

### 3.2. Infratuzilma va ishonchlilik
- **Git va kod ombori** (yopiq GitHub/GitLab) — kodni saqlash, yordamchi dasturchilar bilan ishlash. *Hozir kompyuterda git yo'q.*
- **Server** O'zbekistonda, **PostgreSQL** baza, **domen va HTTPS**.
- **Zaxira nusxa** har kuni, tiklashni sinab ko'rish.
- **Monitoring:** xatolar haqida avtomatik xabar (masalan Sentry), server holati.
- **Sinov muhiti (staging):** yangi o'zgarish avval sinovda, keyin asosiy saytda.
- **Avtomatik tekshiruv (CI):** har o'zgarishda testlar o'zi ishga tushadi.
- **Yuklama sinovi:** 400–600 kishi bir vaqtda natijani ochganda tezlik.

### 3.3. Xavfsizlik va huquqiy masalalar
- **Shaxsiy ma'lumotlar qonunchiligi:** server O'zbekistonda bo'lishi; shaxsiy ma'lumotlar bazasini davlat reyestrida ro'yxatdan o'tkazish talabini yurist bilan tekshirish kerak.
- **Maxfiylik siyosati** va foydalanish shartlari (xodimlar roziligi).
- **Kitoblar mualliflik huquqi** — faqat ruxsat bor kitoblar.
- Mustaqil xavfsizlik tekshiruvi (ishga tushirishdan oldin).

### 3.4. Ishga tushirish jarayoni
1. **Pilot:** bitta liga o'yinini qog'oz bilan parallel tizimda hisoblash — natijalar mos kelishi kerak.
2. Tashkiliy guruh va hisob hay'ati uchun **qisqa o'quv** va yo'riqnoma.
3. Xodimlar uchun "qanday kiraman" qo'llanmasi (1 sahifa, rasmli).
4. Fikr-mulohaza yig'ish → tuzatish → hamma uchun ochish.
5. Yordam kanali (Telegram guruh) va mas'ul admin.
